Import, export & publishing

Your notes are yours. Take a single notebook or your whole vault out to open files, bring them back in, or publish a read-only copy of one note to the web behind a private code.

Export

You can export a single notebook or your entire vault, in any of three formats.

  • One notebook — hover the notebook in the sidebar, open its ⋯ menu and choose Export…. Pick a format and choose where to save the file.
  • Whole vault — open Settings and use Export vault. Every notebook plus its attachments is bundled into a single .zip, with folders that mirror how your notebooks are nested.
FormatWhat you get
Markdown .mdPortable plain text that opens in any editor. A vault export becomes a folder tree of .md files.
HTML .htmlA self-contained web page you can open in any browser — good for reading and sharing, but read-only (see the note below).
JSON .jsonA lossless backup that keeps everything and can be imported straight back into Nomima. The recommended choice for a backup.

What's included. Your blocks and their text, and the Smart Tags (@mentions, #hashtags) inside them, are all serialized. A whole-vault export also copies in every attached file under an assets/ folder, and writes a manifest.json index so Nomima can rebuild your notebook hierarchy on import. A single-notebook export contains just that notebook's document.

Note: HTML is a one-way format — it's meant for reading, not re-importing. For a backup you can restore, export as JSON (or a JSON/Markdown vault .zip).

Import

Import lives in Settings → Import…. It opens a file picker; choose what to bring in and Nomima recreates the notebooks in your vault.

  • A Nomima export — a single notebook as .json (lossless) or .md (best-effort from Markdown).
  • A whole vault — a vault export .zip. Every notebook in the archive is restored, and its nesting (which notebook lives inside which) is rebuilt from the manifest.

A single file lands at the top level of your vault. What round-trips cleanly is your structure, content and hierarchy — from JSON and Markdown sources. Two honest limits: a JSON or Markdown-format vault .zip re-imports, but an HTML export does not (Nomima will tell you to re-export as JSON or Markdown), and attached files are not yet re-imported — only the notebook documents come back for now.

Coming later: importing directly from Obsidian or Notion is not supported yet — it's a planned addition. For now, bring notes in as Markdown or as a Nomima export.

Publishing a note to the web

Publishing puts a read-only copy of one notebook online at read.nomima.io, behind a private code, so you can share a page without giving anyone access to your vault. It's opt-in per notebook — nothing goes online until you publish it, and it's free.

Open a notebook, use its header menu and choose Publish notebook…, then press Publish in the dialog. You get back a shareable link and a view code — a page opens only for someone who has both.

The shareable link & view code

You'll see three things to copy:

  • Link with code — a one-click link that opens the page directly (the code rides in the URL fragment, so it stays out of server logs).
  • Link (prompts for the code) — the plain link; whoever opens it is asked to type the view code.
  • View code — the code itself, to share separately (over a different channel) when you want the extra layer.

Optionally, tick any of the notebook's attached files in the downloads checklist to make them downloadable on the published page. They're off by default.

Updating, unpublishing & the offline outbox

  • Updating — once a notebook is published, your edits keep the public page in sync automatically. You can also press Update now in the dialog to push the latest version immediately.
  • Unpublishing — press Unpublish to take the page offline. The link stops working.
  • Offline outbox — if you publish or update while offline, the change is queued and sent automatically the moment you reconnect. You don't have to retry by hand; the dialog shows the queued state until it goes through.

What gets captured: publishing takes a self-contained snapshot of the note exactly as it appears on your screen — rendered diagrams, dashboard numbers, pills and image thumbnails, in your current theme — with all editing controls removed. The reader sees that snapshot, not your live vault, and only the one notebook you chose to publish.

Keep in mind: anyone with both the link and the view code can read the page. Share the code through a separate channel from the link when a note is sensitive, and unpublish when you're done.
