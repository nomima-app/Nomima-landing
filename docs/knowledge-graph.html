Knowledge Graph

A living map of everything you’ve written — every person, project, date, file and note, connected. You never build it; it builds itself while you write.

It builds itself

Every time you save or leave a note, Nomima indexes just that note: its tags, dates, tasks, files and links become entities and connections in the graph. There is no “sync” or “generate” button — by the time you open the graph, it already reflects your latest edit. Entities mentioned in the same block get connected, and attached files and RSS articles contribute entities from their text too.

How indexing works

Nomima's indexing pipeline runs in two layers. Both happen automatically — you never trigger them manually.

Layer 1 — Structural index (instant)

The moment you save or leave a note, Nomima parses it and writes the structural index: every @mention, #hashtag, date pill, task, reminder and file attachment is recorded as an entity or relationship in the local SQLite database. This is why Smart Views, Home, the scrollbar minimap and the relational graph update instantly — no processing lag at all.

Layer 2 — Semantic index (background)

In the background, each block of text is also embedded: converted into a dense vector of numbers that captures its meaning, then stored in the local vector database. This powers:

  • Semantic search — Summon finds notes by meaning, not just keywords (“find my thoughts on team dynamics” surfaces notes without that exact phrase).
  • Similar nodes in the graph — the Semantic mode of the Knowledge Graph draws connections between entities that appear in semantically similar contexts, not just those that share a tag. Two notes about the same person but using different names can still cluster together.
  • Deep research — when Summon does multi-step vault research, it retrieves by embedding similarity first, then reads the full blocks.

Embedding is done entirely on your Mac — the same local language model that runs the Knowledge Graph. Nothing is sent to any cloud for this step, even if you have a cloud AI key configured.

File ingestion

When you attach a file (drag-drop, /file, or paste), Nomima ingests it in three steps:

  1. Extract — text is pulled from the file (PDF pages, Word paragraphs, Markdown headings, code comments, spreadsheet cells…) and stored locally.
  2. Chunk — the extracted text is split into meaningful segments (a few paragraphs each) that fit the embedding model's context window.
  3. Embed — each chunk is vectorized and stored. From this point on the file's content is fully searchable, and its entities join the Knowledge Graph.

The Files lens in Smart View shows the state of every file: Embedded (all three steps done), Processing (in progress), or No text (binary/image — stored, but nothing to extract).

The background queue & offline behaviour

Embedding is compute-intensive, so Nomima processes it in a background queue at low priority — it never slows down your typing or the app's responsiveness. A few things to know:

  • Notes index instantly, embeddings follow. After saving a note you can immediately use Smart Views and the relational graph — those use the structural index. The semantic layer (Summon's meaning-based search, semantic graph mode) catches up within seconds in the background.
  • Offline is fine. The queue runs entirely on-device; there's nothing to wait for from the network. If you write without any AI configured, the embedding step still runs using the bundled local model.
  • Bulk imports queue gracefully. Drop 50 PDFs at once — they all enter the queue and process one-by-one without blocking anything. Watch the Files lens to see progress.
  • Queue survives restarts. Unfinished jobs are persisted. If you quit Nomima mid-import, the queue resumes exactly where it left off on next launch.
  • Re-index (Settings → Vault) wipes and rebuilds both layers from scratch — the only manual intervention that ever exists, and rarely needed.

Reading the graph

  • Nodes are entities — glowing orbs colored by type, using the exact same colors as the pills in your notes (including your custom types). The legend in the corner lists every type present with its count.
  • Size means connectedness — the more an entity appears across your vault, the bigger its node.
  • Grey means done — completed items dim, so the bright part of your graph is the live part.
  • Edges are relationships — curved lines with animated particles flowing along the connections of whatever you’ve selected.

The entity panel

Clicking a node opens a panel showing the entity’s name, type and connection count, plus its relationships grouped by kind — Appears in, Assigned to, Due, Related and so on. Every related item is clickable: hop from a person to a project to the note where they intersect. This is the same entity card you get by clicking a pill in the editor — including its custom attributes (see Mentions & hashtags).

The in-note cover graph

Each notebook can show a compact graph above the page — just that note’s entities and their immediate connections. It’s fully interactive (drag to pan, drag nodes, click to inspect, ⌘+scroll to zoom), and when you scroll down to write, it parks itself to keep the editor fast.

If something looks off

Settings → Vault → Re-index rebuilds the entire graph from scratch, deterministically. It’s the only manual maintenance action in Nomima and exists as a safety net — day to day, the graph keeps itself current.

Privacy: the graph is computed entirely on your Mac. Nothing about your notes — entities and relationships — ever leaves your device. See Settings & privacy.
